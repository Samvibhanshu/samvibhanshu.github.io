Selected work

All 12 projects

Backend systems in Java with no frameworks, so every line is visible: one that survives crashes, its AWS version, and a queue the official AWS SDK can talk to. Next to each is what backs it up.

  • Order service

    Place, pay, ship and cancel orders over a JSON HTTP API. It never oversells under concurrency, never charges twice when a payment is retried, only allows legal state changes, and keeps every acknowledged order through a crash with a write-ahead log.

    Java 17, java.util.concurrent, JDK HTTP server

    How it worksCode on GitHub

    44 testsKilled with kill -9 mid-traffic, four times: no acknowledged order lost

  • Order service on AWS

    The order service as a serverless AWS service: API Gateway, Lambda (Java) and DynamoDB in one SAM template. No overselling and no double charge across any number of Lambda instances, enforced by DynamoDB conditional writes and transactions. AWS request signing written from scratch.

    Java 17, AWS Lambda, API Gateway, DynamoDB, SAM

    How it worksCode on GitHub

    18 tests32 requests race for the last 20 units against DynamoDB's API: exactly 20 succeed

  • Mini-SQS

    A message queue with Amazon SQS semantics: visibility timeouts, receipt handles, dead-letter queues and redrive, FIFO groups with deduplication, long polling. It runs as a library or as a network service that speaks SQS's own protocol, so the official AWS SDK can use it.

    Java 17, no dependencies

    How it worksCode on GitHub

    39 testsThe AWS SDK for Python passes 27 checks against it; 600 random sequences lose no message

  • Agentic bug repair

    Takes a Java repository with failing tests and tries to fix it: measures which methods each test runs, ranks where the bug probably is, tries small patches in an isolated sandbox, and only proposes a pull request whose diff passes every test on a clean checkout.

    Java 17, JDK compiler API, Linux namespaces, JavaScript

    How it worksCode on GitHub

How I work

Prove the hard part

In order service, 64 threads race for the last 50 units on every test run, and the server is killed with kill -9 mid-traffic without losing an order it confirmed.

Test the tests

I plant bugs to see whether my tests notice. In Mini-SQS they caught all 11; in route planner 9 of 11, and the other two cannot change behaviour.

Measure, then improve

Agentic bug repair has a 20-bug benchmark of its own; re-tuning it on a development split doubled its correct fixes, from 4 to 8, and the held-out split confirms the gain.
